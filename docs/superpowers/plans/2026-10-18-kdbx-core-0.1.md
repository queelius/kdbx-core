# kdbx-core 0.1 implementation plan

Spec: `docs/superpowers/specs/2026-10-18-kdbx-core-design.md` (read it first; it is canonical). This plan covers sequencing step 1 of the spec (kdbx-core itself). diff-kdbx, mcp-kdbx and web-kdbx adoption get their own plans.

## Ground rules

- Test-first for every task: write the failing test, watch it fail, implement, watch it pass.
- One conventional commit per task (`feat(path): ...`, `test(capture): ...`). Every commit ends with the session trailers given in the dispatch prompt.
- No em-dash characters in any file or commit message.
- Library is I/O-free and WASM-compatible with default features; CI checks `cargo build --target wasm32-unknown-unknown --no-default-features` and with `--features kdf`.
- `#[non_exhaustive]` on every public struct and enum that may grow. No `pub` field whose invariants a caller could break (use constructors).
- Edition 2024, `rust-version = "1.89"` (keepass 0.15 requires it), license MIT with a LICENSE file, author "Alexander Towell <lex@metafunctor.com>", repository `https://github.com/queelius/kdbx-core`.
- Dependencies stay lean: serde, uuid, chrono (no default features), sha2, hmac, zeroize, unicode-normalization, unicode-properties; argon2 behind `kdf` (default on); keepass 0.12 and 0.15 as package-renamed optional deps behind `keepass-0_12` / `keepass-0_15`. OTP needs SHA-1/SHA-256/SHA-512 HMAC and base32: prefer small, WASM-friendly crates; justify each new one in Cargo.toml comments.

Gates before each commit: `cargo fmt --check`; `cargo clippy --all-targets --all-features -- -D warnings`; `cargo test --all-features`; `cargo test --no-default-features`; the two wasm32 builds; `cargo doc --no-deps --all-features` with no warnings.

## Tasks

1. **Scaffold.** `Cargo.toml` (features: `default = ["kdf"]`, `kdf`, `keepass-0_12`, `keepass-0_15`), `src/lib.rs` with module skeletons and crate docs, `LICENSE`, `README.md` (what it is, the layering diagram from the spec, feature table), `CLAUDE.md` (orientation, invariants below, commands), `CHANGELOG.md`, `.github/workflows/ci.yml` running the gates (including a job with each keepass feature alone and both together). Commit.
2. **`text`.** `escape_inline` and `continuation_lines` per spec 3.6. Escapes: `\\` for backslash, `\n \t \r`, `\u{XXXX}` for other Cc and Cf. Property tests (proptest): output of `escape_inline` contains no Cc/Cf; `continuation_lines` yields lines that all start with the prefix, and joining them reverses the split. Commit.
3. **`fields`.** `StandardField`, `FieldTraits`, `traits_of`, per spec 3.2. Notes is multiline; custom fields default to single-line, not protected (a value containing a newline is rendered multiline by callers; traits describe defaults). Test against `keepass::db::fields::KNOWN_FIELDS` under each keepass feature. Commit.
4. **`fingerprint`.** `FingerprintKey` (32 bytes, `Zeroize` on drop, redacting `Debug`, no `Clone` unless needed), `Fingerprint` (32 bytes, `short()`, hex `Serialize`/`Deserialize`, constant-time `PartialEq` via `subtle` or hmac's verify), `Domain` enum (Field, Attachment, CustomData), `FingerprintKey::fingerprint(domain, bytes)`. `derive(&KeyMaterial, salt: Uuid)` under `kdf`: Argon2id, 64 MiB, t=3, p=1, output 32 bytes, input `SHA-256(password) || SHA-256(keyfile)` with absent parts as 32 zero bytes, salt `b"kdbx-core/fingerprint/v1" || uuid bytes`. Pin known-answer vectors (fixed key and input, fixed derive output) so the format can never drift silently. Commit.
5. **`model`.** All snapshot types from spec 3.1 (`Snapshot`, `FormatVersion`, `Meta`, `MemoryProtection`, `Group`, `GroupFlags`, `Entry`, `Field`, `Value`, `AttachmentInfo`, `CustomValue`, `Times`, `Timestamp`, `Icon` (`Standard(u32)` / `Custom(Uuid)`), `Rgb` (Display as `#RRGGBB`), `AutoType`, `AutoTypeAssociation`, `Sealing`). Derive `Serialize`/`Deserialize` (document shape as unstable before 1.0). Provide read-only accessors and iteration helpers: `Snapshot::walk()` yielding `(NodeRef, parent_uuid)` in document order, `Snapshot::find(uuid)`. Builders for tests (`Snapshot::builder()` or plain constructors behind a `test-util` feature) so downstream crates can build snapshots without keepass. Commit.
6. **`visibility`.** `metadata_value` per spec 3.3, with the Title exception, and `is_visible(&Field, name)`. Tests: protected UserName/URL/Notes/custom hidden; Title visible even when protected; sealed values never visible. Commit.
7. **`path`.** Port mcp-kdbx's grammar. Source of truth: `/tmp/claude-1000/-home-spinoza-github-kdbx/2cd1582c-eef4-480d-bffd-1d5658fa1eb0/scratchpad/p0/mcp-kdbx/src/kdbx_core/path.rs` (the reviewed fix-branch version, including the empty-segment and group-shaped-path rules); read it, do not modify it. Changes from mcp: typed `PathError` and `ResolveError` enums instead of mcp's `CoreError`; resolution against `Snapshot` (returns `NodeRef` or the node's UUID); add control-character escapes consistent with `text::escape_inline`; `path_of(snap, uuid) -> Option<VaultPath>` returning `None` for any node whose ancestry contains an empty name. Port all of mcp's path tests (adapting the fixture setup to snapshot builders) and add: proptest `parse(format(p)) == p`; ordinals by UUID; NFC equivalence; empty-name nodes have no path; injection-shaped input fails to resolve. Commit.
8. **`capture`.** `keepass_0_12::capture` and `keepass_0_15::capture` per spec 3.8, generated from one `macro_rules!` body with small per-version shims. Map every model field. Sealing: protected field values, attachment contents and custom-data values become `Value::Sealed` under `Sealing::Fingerprint`; Title stays plain. Also `otp_fields(&EntryRef) -> BTreeMap<String, String>` returning only OTP-related fields in plaintext (for OTP under fingerprint sealing). Tests per version: build databases in-test with fixed UUIDs (`add_entry_with_id`, `Database::new_with_root_id`), assert a full snapshot equality; open corpus files (task 10) and assert key facts; assert that a capture under `Fingerprint` serialized to JSON contains none of the protected plaintexts (search the JSON for each secret). Commit.
9. **`otp`.** Port mcp-kdbx's TOTP. Source of truth: `.../scratchpad/p0/mcp-kdbx/src/kdbx_core/totp.rs` (fix-branch version with base32 normalization and `TimeOtp-*`). Make it keepass-free: `resolve(fields: &BTreeMap<String, String>)` or over a `Reveal` snapshot entry, typed `OtpError`, `TotpConfig::code_at(unix_time)` with no clock access. Port all tests including the RFC 6238 vectors. Commit.
10. **Corpus.** `tests/corpus/` with `MANIFEST.md` (file, origin, license, password or key file, KDBX version, what it exercises, SHA-256) and a test that verifies every checksum. Sources (copy, never modify the originals): from `/home/spinoza/github/bugfixes/track1-issues/keepass-rs/tests/resources/` (MIT, upstream keepass-rs; record the upstream commit): `test_db_kdbx41_features.kdbx` (written by KeePassXC 2.7.12), `test_db_kdbx4_with_password_argon2.kdbx`, `test_db_kdbx4_with_totp_entry.kdbx`, `test_db_kdbx4_with_keyfile_v2.kdbx` with its `.keyx`, `test_db_kdbx3_with_attachments.kdbx`, `test_db_kdbx4_with_password_deleted_entry.kdbx`; from diff-kdbx: `tests/fixtures/legacy_kdbx40/vault.kdbx`. Generate additional fixtures where coverage is missing (protected UserName/URL/Notes, legacy `TOTP Seed`/`TOTP Settings`, `TimeOtp-*`, duplicate titles, untitled entry, history of 12 items) with an `examples/gen_corpus.rs` using keepass 0.12 (so they are KDBX 4.0) and fixed UUIDs; commit the outputs. Commit.
11. **Docs and wrap-up.** Rustdoc on every public item with examples where useful (doc tests run in CI). README feature table and examples. CLAUDE.md test counts. CHANGELOG `[0.1.0] - unreleased`. `cargo package --list` review (no fixtures over what is needed; consider `exclude = ["tests/corpus/*.kdbx"]` if size matters, keeping the tests runnable from the repo). Commit.

## Invariants to preserve (put these in CLAUDE.md)

- Plaintext of a protected value enters a snapshot only under `Sealing::Reveal`.
- Title is an address, never a secret (spec 3.1).
- One visibility rule, one path grammar, one escape function: no member re-implements them.
- Fingerprints are keyed. Nothing in the crate exposes an unkeyed hash of a secret.
- Default features pull in no keepass.
